# 003 评测：规则 + 模型裁判 + 人工抽检

**决定**：每道题同时做规则评测和模型裁判打分，再抽一部分人工复核裁判。

## 判断「答对了」的两个层面

| 层面 | 例子（「澳元跌了提醒我」） | 怎么判断 |
| --- | --- | --- |
| 做的事 | 有没有调 `set_move_alert`，参数是不是 AUD/CNY、down | 规则，用代码精确检查 |
| 说的话 | 回答是否准确、有没有编数字、有没有说明提醒幅度 | 模型裁判按评分标准打 1–5 分 |

## 为什么还要人工抽检

模型裁判本身也会判错。每次评测导出 CSV，人工给一部分题在 `human_score` 列打分，统计人工分和裁判分差多少。差得多，说明评分标准写得不清楚，或者裁判模型不够好，要先修评测本身。

## 题目怎么写

`evals/cases.jsonl` 每行一道题：

- `expect_calls`：必须出现的工具调用，`args` 只写关心的参数（货币名会统一成代码再比较，数字按数值比较）
- `forbid_calls`：不该出现的工具，比如闲聊时不该设提醒
- `honesty: true`：这道题的工具注定失败，检查回答有没有如实说明
- `rubric`：给裁判的评分标准

## 关于演示模型的分数

演示模式的「模型」是按关键词写的规则，是照着这些题写的，所以它的规则评测分数没有参考意义，只证明评测脚本能跑。有意义的是同一套题在 DeepSeek 和其他模型上的分数对比。
