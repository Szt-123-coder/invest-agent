# 004 结构化输出：回答按固定格式交，依据要注明出处

**决定**：最终回答不再是一段自由文字，而是 `app/answer.py` 里的 `Answer`：结论、依据、风险、信心、执行结果。依据里每个数字都要写明来自哪个工具，评测用代码逐个核对。

## 为什么

| 自由文字的问题 | 固定格式怎么解决 |
| --- | --- |
| 页面只能显示一大段字 | 显示成卡片，依据是一张表 |
| 「数字是不是编的」只能靠模型裁判判断 | 每个数字注明工具，代码去那个工具的返回结果里找，找不到就是编的 |
| 设提醒成没成功，要从文字里猜 | `actions` 里有 `ok` 字段，和工具返回的 `ok` 对比 |

## 怎么实现

LangChain `create_agent` 的 `response_format=ToolStrategy(Answer)`：把 `Answer` 变成一个「交卷工具」。模型查完数据后调用它，参数就是结构化的回答；参数不符合格式时 LangChain 会把错误告诉模型，让它重填。

没有用模型自带的 JSON 模式（`ProviderStrategy`），因为 DeepSeek 等很多兼容 OpenAI 的接口不支持按 JSON Schema 输出，但它们都支持工具调用。

## 历史相似情形

sand 提出：依据和风险能不能参考过去的真实案例？可以，但不能让模型凭记忆写（会编出看起来很真的历史数字，而且没法核对）。所以新增了工具 `find_similar_history`：在过去几年的价格里找和现在相似的时候（最近 30 个交易日涨跌幅接近、在区间里的位置接近），统计之后 30 天的涨跌。它返回的次数、上涨比例、平均涨跌都能被评测核对。

已知局限：

- 只看价格形态，不看当时的新闻和利率环境
- 「相似」的标准是人定的（涨跌幅相差不超过历史波动的 1/4，位置相差不超过 20 个百分点），换标准结果会变
- 样本少（少于 8 次）时工具会提示不可靠，模型要写进风险

## 怎么验证

- `tests/test_jobs_and_eval.py`：编造的数字、注明了没调用过的工具、执行结果谎报成功，都会被规则抓到；四舍五入的数字不会被误判
- `tests/test_agent.py`：「要不要换」类问题会调用 4 个工具，依据覆盖查价、走势、历史相似情形三个来源

## 第一次在 DeepSeek 上跑：18/22，3 道是核对规则写死了

| 题目 | 被判错的原因 | 实际情况 | 改法 |
| --- | --- | --- | --- |
| 澳元为什么涨、只看新闻 | 新闻里的数字（中间价 6.7351、年内升值 4%）「找不到」 | 用的是真实 Tavily 新闻，数字写在新闻摘要的文字里，规则只认 JSON 里的数值字段 | 文字里的数字也算 |
| 闲聊 | 「当前提醒数量 0」找不到 | 0 是提醒列表的长度，不是一个字段 | 列表长度也算 |
| 我的提醒有哪些 | 执行结果写了成功，但没有修改成功 | 模型把「查看提醒」这种查询也填进了 `actions` | 字段说明和提示词写明：只填修改类操作 |

放宽「文字里的数字也算」有代价：新闻正文数字很多，编出来的数字碰巧和正文里某个数一样时会漏判。这里选择接受，因为把真实引用判成编造，比偶尔漏判一次更伤评测的可信度。

## 第二次跑：23/24，模型查完数据却没交卷

「澳元为什么最近涨了？」这题，DeepSeek 调了 7 次工具（查价、走势、3 次新闻、澳元兑美元），然后图就结束了：既没调用 Answer，也没说话。规则正确地判了「没有按固定格式交出回答」。

改法：`run_stream` 结束时如果还没有回答，先记一条提示（含模型的停止原因 finish_reason，方便下次排查），再把问题和所有工具结果整理成一段文字，只给模型一个 Answer 工具让它补交。补交成功时评测不算错，但 CSV 的 problems 列会写「提示：…补交」，这样补交频率也能被看到；如果某道题经常靠补交，说明提示词或工具描述还要改。
