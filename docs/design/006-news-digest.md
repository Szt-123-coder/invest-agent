# 006 每日新闻摘要：固定流程，模型只做提炼

**决定**：每天定时给关注的标的搜新闻，让模型提炼「发生了什么、影响哪个标的、偏涨还是偏跌」，代码核对后推送到微信。代码在 `app/digest.py`，页面是 `/digest`。

## 为什么不用 agent

问答需要 agent，因为每个问题要查的东西不一样，得让模型自己决定下一步。每日摘要的步骤每天都一样：

```
关注列表 → 每个标的搜新闻（去重、编号） → 模型一次提炼全部新闻 → 代码核对 → 存库 → 推送
```

步骤固定时用固定流程（workflow）更合适：只调一次模型，便宜；不会出现「查完不交卷」或多调工具的情况；每一步的输入输出都固定，好测试、好评测。模型只做它擅长、代码做不了的那一步：读懂新闻并判断影响。

## 怎么防止模型编新闻

| 风险 | 做法 |
| --- | --- |
| 编出一条不存在的新闻或链接 | 新闻先编号再给模型，模型只能填编号；标题和链接由代码按编号填回去 |
| 说影响了没关注的标的 | `symbol` 必须在关注列表里，否则丢掉 |
| 同一条新闻重复出现 | 搜索时按链接去重；提炼结果按（编号，标的）去重 |
| 方向硬猜 | 方向只能是「偏涨 / 偏跌 / 看不出」，提示词要求拿不准就填看不出 |

丢掉的每一项都记下原因，显示在页面上。「丢掉几项」本身就是一个自动的质量指标：长期偏高说明提示词要改。

「偏涨 / 偏跌」而不是「利好 / 利空」：货币对的利好对谁好容易说不清（澳元走强对换澳元的人是坏事），所以直接说价格方向，货币对 AUD/CNY 偏涨就是澳元相对人民币走强。

## 关注话题

除了币和股票，还可以关注新闻话题（「帮我留意澳洲联储利率的新闻」，工具 `watch_topic`）。sand 在两种设计里选了「话题单独列」：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A 话题单独列（选了这个）** | 话题单独搜新闻，模型判断每条影响哪个关注的标的 | 一个话题可以影响多个标的（美联储加息同时影响美元和英伟达）；「判断影响谁」正是要展示的能力 |
| B 挂在标的下面 | 话题只用来缩小某个标的的搜索范围 | 做起来简单，但同一个话题要给每个标的各设一遍 |

话题新闻和标的新闻放在一起编号，交给模型同一次提炼。模型判断对所有关注标的都没影响的话题新闻，不丢掉，而是在「话题」一栏列出标题，让用户知道搜过了、没有漏。

## 定时

`DIGEST_TIMES=08:00,23:00`（按 `TIMEZONE` 的当地时间）。后台每分钟看一次：过了某个时间点、且那之后还没发过，就发一份。超过 1 小时就不补发，避免服务停了半天后启动时发一份过时的摘要。

## 已知局限

- 方向是模型对新闻的解读，不是预测；新闻多是媒体观点，可能互相矛盾
- 搜索结果取决于 Tavily，关键词是代码按标的拼的（「澳元 人民币 汇率」），可能漏掉相关但用词不同的新闻
- 还没有针对摘要的评测题。下一步：固定一批新闻做输入，标好每条的正确标的和方向，看模型提炼的准确率，再和规则方法对比（v2 的异常检测也会用同样的思路）
